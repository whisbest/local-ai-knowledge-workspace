# 本机数据与恢复

应用数据在项目 `data` 下（可通过 DATA_PATH 修改本机绝对路径），当前集合为 `state/current`：SQLite WAL、原文件副本和解析文本。片段、向量、配置、消息与不可变引用快照在数据库中。普通停止或重建容器不删除这些文件。

数据设置可查看宿主机路径、空间和类别统计，按索引/文档/对话/全部业务数据预览后确认清理。只清理索引保留原文和对话，需在处理页选择文档重建。

默认 ZIP 备份不含 API 密钥、Ollama 模型权重、日志或其他备份。创建备份时暂停新任务与请求；运行中的任务须等待完成或用户主动停止，使用 SQLite backup API 获取一致快照，复制原文件与解析，记录 SHA256 和格式版本。

恢复采用覆盖方式，先上传到暂存集合检查 ZIP 路径、大小、清单、校验值、数据库完整性及关联。预览并确认后创建恢复前备份，再切换数据集合。交换过程的日志保存在挂载根目录内部，异常回滚，进程崩溃后启动优先恢复旧集合。旧数据集合保留在 rollback 中，方便进一步核查。

恢复后 API 配置不会使用本机原有密钥，需重新配置。已有索引与关联保留；本地模型必须仍在 Ollama 中存在，能力测试和模型服务调用可检查缺失状态。禁止把密钥目录手动加入分享给他人的备份。

损坏、不兼容、超过 2GB 展开大小/10000 文件的备份拒绝导入。备份写入失败不进行覆盖。手工测试故障只能在独立临时目录执行，不能使用个人正式资料。
